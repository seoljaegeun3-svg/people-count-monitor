# People Count Monitor

Windows에서 **왼쪽 카메라 웹 뷰어 · 오른쪽 웹 탭 · 아래 LS PLC `%MW0`**를 함께 보고 프로그램 창 전체를 녹화하는 데스크톱 프로그램입니다.

## 실행

**일반 사용자는 [Windows 다운로드 페이지](https://github.com/seoljaegeun3-svg/people-count-monitor/releases/latest)의 Assets에서 `People-Count-Monitor-1.2.0.exe`를 받아 더블클릭하세요. Node.js나 영상 변환기를 따로 설치할 필요가 없습니다.** Source code ZIP은 실행 파일이 아닙니다.

아래 명령은 소스 코드를 개발하거나 직접 빌드할 때만 사용합니다.

Node.js 22 이상을 설치하고 이 폴더에서:

```powershell
npm ci
npm start
```

배포용 Windows EXE는 Windows PC에서 다음 명령으로 만듭니다.

```powershell
npm run dist:win
```

결과: `dist/People-Count-Monitor-1.2.0.exe`. 수신 PC에는 Node.js가 필요 없습니다. EXE는 코드 서명되지 않습니다. Windows 배포는 Windows에서 `npm ci`로 받은 Windows용 내장 변환기를 사용해야 합니다.

GitHub의 **Actions → Build Windows download → Run workflow**로도 Windows 빌드·모의 PLC 테스트·EXE 배포를 실행할 수 있습니다. 실패한 빌드는 새 다운로드를 게시하지 않습니다.

## 사용 방법

1. 카메라·PLC가 연결된 Windows PC에서 실행합니다.
2. 기본 주소 `http://192.168.1.100/`에서 시작합니다. 카메라가 HTTP Basic/Digest 인증을 요구하면 앱의 **카메라 로그인** 창에 카메라 아이디·비밀번호를 입력합니다. 웹 로그인 화면이 나오면 그 화면에서 로그인합니다. 로그인 후 왼쪽 상단 **피플카운팅**을 누르면 스크린샷의 WiseAI 페이지를 엽니다. **로그인 / 홈**은 카메라 로그인 시작 화면으로 돌아갑니다. 비밀번호를 주소에 넣지 마세요.
3. 오른쪽 주소창에 검색어를 입력하고 Enter 또는 **이동**을 누르면 구글에서 검색합니다. `google.com` 같은 웹 주소나 YouTube 영상 URL도 열 수 있습니다. 상단 **Google / YouTube** 버튼으로 바로 이동하고, 뒤로/앞으로/새로고침을 사용할 수 있습니다. 새 창으로 열리는 검색 결과는 같은 오른쪽 화면에 표시합니다. **연결 설정 → 브라우저 시작 주소 또는 검색어**에서 시작 화면을 바꿀 수 있습니다. iframe이 아니라 독립 Chromium 화면을 사용합니다. 일부 영상의 DRM·코덱·Google 로그인 정책은 Electron에서 제한될 수 있습니다.
4. **연결 설정**에서 PLC IP·포트·워드·주기를 확인합니다. **PLC 연결**을 누르면 읽기가 시작됩니다. 연결 실패 시 자동으로 다시 조회하며 이전 값을 지웁니다. **연결 중지**로 멈춥니다.
5. 가운데 세로 경계로 **좌우 비율**, 영상과 PLC 사이의 가로 경계로 **위아래 비율**을 조절합니다. 키보드로는 경계에 포커스한 뒤 해당 방향키를 사용합니다. 창의 위·아래 테두리를 끌어 높이도 줄일 수 있습니다(최소 창 크기 860×500). 비율은 자동으로 기억합니다. 카메라 상단의 `− / ＋`는 페이지 크기를 조절합니다.
6. **웹 창 추가** 또는 탭 옆 **＋**로 웹 탭을 추가하고 **×**로 닫습니다. 모든 탭을 닫으면 오른쪽 영역이 사라지고 카메라가 넓어집니다. **웹 창 추가**로 다시 열 수 있습니다. 오른쪽 영역을 닫았는지는 다음 실행에도 기억합니다. 열린 개별 탭 목록은 종료 시 초기화하며 시작 주소 설정을 사용합니다. 탭은 최대 12개입니다.

## 프로그램 녹화

1. 상단 **● 녹화 시작**을 누르고 저장 위치와 새 파일 이름을 선택합니다.
2. **녹화 중** 시간 표시를 확인합니다. 화면에 보이는 카메라·선택된 웹 탭·PLC 값·상태가 함께 녹화됩니다.
3. **■ 중지**를 누르고 **MP4 변환 중 → 저장 완료**를 기다립니다. 녹화 길이와 PC 성능에 따라 변환 시간이 걸릴 수 있습니다. **저장 폴더**로 파일을 찾을 수 있습니다.

저장 형식은 **MP4(H.264 영상 / 선택형 AAC 소리)**입니다. 전체 길이와 탐색 정보를 포함하므로 플레이어의 재생 막대를 움직여 앞뒤 원하는 시점으로 이동할 수 있습니다. 기본 저장 위치는 Windows 동영상 폴더이며 다른 폴더도 선택할 수 있습니다. 같은 이름의 기존 파일을 덮어쓰지 않으므로 새 파일 이름으로 저장하세요. 창을 최소화하면 정상적으로 캡처되지 않을 수 있으니 녹화 중에는 창을 열어두세요.

**기존 녹화 파일:** 상단 **MP4 변환**을 누르고 이전 버전으로 저장한 `.webm` 파일을 선택한 뒤 새 `.mp4` 저장 위치를 고릅니다. 변환이 완료되면 **저장 폴더**를 누르세요. 기존 WebM 원본은 유지합니다. 파일 확장자만 바꾸는 방식으로는 변환되지 않습니다.

**PC 소리 포함**은 기본적으로 꺼져 있습니다. 켜면 Windows의 PC 재생음을 함께 녹음하므로 다른 앱 소리도 포함될 수 있습니다. PC 소리를 지원하지 않는 장치에서 시작 오류가 나면 체크를 해제하고 다시 시작하세요. 마이크 녹음은 하지 않습니다. 사용 중인 프로그램 창만 영상으로 캡처하며 다른 프로그램 화면은 선택하거나 녹화하지 않습니다.

녹화 중에는 같은 폴더에 WebM 원본을 나누어 기록하고, 중지 후 내장 FFmpeg로 MP4를 완성합니다. 긴 녹화 전체를 메모리에 쌓지 않습니다. MP4 저장이 성공한 뒤 녹화 임시 원본을 정리하며, 변환 실패 시 복구용 WebM 원본을 보존합니다. 저장 공간은 변환 중 원본과 MP4가 함께 들어갈 만큼 필요합니다. 정상적인 창 닫기는 변환을 마친 뒤 종료합니다. 디스크 오류·강제 종료로 남은 불완전한 원본의 재생·변환 가능 여부는 중단 시점에 따라 다릅니다.

## 통행 자동 녹화

1. 카메라 화면을 연 상태에서 **화면 아래 왼쪽 → 자동 녹화 OFF · 켜기**를 누르고 MP4 저장 폴더를 선택합니다. PLC 읽기도 시작됩니다.
2. **자동 녹화 ON · 끄기**가 표시되면 대기 상태입니다. PLC 값이 처음 읽힌 때에는 기준값만 기억합니다.
3. `%MW0` 값이 증가하거나 감소하면 **변화 전 5초부터 마지막 변화 후 10초까지** 프로그램 화면을 MP4로 자동 저장합니다. 사람이 연달아 지나가면 종료 시점이 연장되어 한 영상으로 묶입니다. 통행이 계속되면 최대 60초 단위로 나눕니다.
4. **자동 녹화 ON · 끄기**를 누르면 현재 구간과 저장 대기를 마친 뒤 꺼집니다. **저장 폴더**로 자동 생성된 MP4를 찾을 수 있습니다. 수동 녹화는 자동 녹화를 끈 뒤 사용할 수 있습니다.

이 기능은 **PLC 값의 변화**를 기준으로 합니다. 사용자가 확인한 입장·퇴장에 따른 `%MW0` 증감을 이용하며, 영상 자체에서 사람을 판별하지는 않습니다. PLC 연결이 끊기면 감지를 대기하고 재연결 후 첫 값은 새 기준으로만 사용합니다. 값 리셋도 변화로 감지합니다. 두 통행이 한 조회 주기 안에 서로 상쇄되어 같은 값으로 돌아오거나 PLC가 변화를 전달하지 않으면 해당 이동은 감지할 수 없습니다.

자동 녹화를 켠 직후에는 확보된 장면부터 시작하며, 약 5초가 지나면 이전 장면까지 보관할 수 있습니다. 대기 영상은 2초 단위 임시 구간으로 돌려 쓰므로 무인 상태의 전체 영상이 계속 쌓이지 않습니다. 저장된 MP4는 자동 삭제하지 않습니다. 정상적으로 끄면 대기용 임시 폴더를 정리합니다. MP4 변환 중에도 다음 통행 수집을 계속하며, 디스크 또는 변환기가 따라가지 못하면 자동 녹화를 중지하고 복구용 원본과 오류를 남깁니다. 강제 종료나 저장 오류로 남은 `People-Count-Recovery-...` 또는 `.people-count-auto-...` 폴더는 원본 확인 전 삭제하지 마세요.

자동 녹화는 **프로그램 실행 때마다 기본 OFF**입니다. 화면 캡처는 켜기 버튼을 누를 때 승인된 프로그램 창으로 한정하며, 녹화 중에는 창을 최소화하지 마세요. PC 소리 포함 설정은 켜기 전에 선택합니다.

기본 PLC 설정은 기존 [people-counter-native](https://github.com/seoljaegeun3-svg/people-counter-native) 저장소의 `plc.go`, `settings.go`에서 확인한 **LS XGT Ethernet / 192.168.1.2:2004 / %MW0 / 500ms**입니다. 실제 장비가 이 설정을 사용한다는 확인은 별도로 필요합니다. Modbus TCP용 프로그램은 아닙니다. unsigned 16-bit WORD 원시값(0~65535)을 표시합니다. PLC 내부 값의 의미와 카메라 IN/OUT 집계의 대응은 현장 로직에 따라 달라집니다.

**PLC 쓰기·리셋 명령은 구현하지 않았습니다.** 카메라 IN/OUT 값은 카메라 페이지에서 확인합니다. 자동 추출·정확도 판정 기능은 없습니다. PLC 읽기는 앱을 시작할 때 자동 연결하지 않으며 사용자가 연결 버튼을 누릅니다.

## 설정과 로그인

Electron 사용자 데이터 폴더(`app.getPath('userData')`)의 `settings.json`에 주소·PLC 설정만 저장합니다. Windows 기본 경로는 `%APPDATA%\People Count Monitor\`입니다. 카메라와 오른쪽 웹 브라우저의 쿠키·로그인 세션은 별도의 로컬 브라우저 프로필에 보관합니다. 기존 YouTube 프로필과 설정은 새 버전에서도 사용합니다. 카메라 비밀번호를 앱 설정에 저장하지 않습니다. 카메라 또는 웹사이트 내 로그아웃을 사용하세요. 인증서 오류를 우회하지 않습니다.

앱 로그인 창은 사용자가 연 카메라 주소와 같은 출처의 Basic/Digest 요청에만 표시됩니다. 다른 서버나 프록시 인증에는 카메라 계정을 전달하지 않습니다. HTTP 인증 정보는 현재 Chromium 세션에 사용되며 앱이 평문 설정 파일에 저장하지 않습니다. HTTP 인증으로 로그인한 경우 프로그램을 종료하면 해당 세션이 끝납니다. 이전 버전의 기본 WiseAI 주소가 저장돼 있으면 새 버전은 카메라 홈부터 시작합니다. `401`은 **로그인 필요**, 다른 HTTP 오류는 **페이지 연결 실패**로 표시합니다.

## 검증

```powershell
npm test
npm run test:camera
# Windows EXE 빌드 후 내장 변환기와 라이선스 포함 검증
npm run test:packaged
```

외부 장비에 연결하지 않는 로컬 모의 XGT 서버로 읽기 패킷, 분할 응답, 0/65535, 호출 ID 불일치, PLC 오류, 잘못된 길이·블록·워드 크기, 중간 연결 종료, 타임아웃을 검증합니다.

`test:camera`는 실제 Electron/Chromium에서 loopback 모의 서버의 Basic/Digest 로그인, 잘못된 비밀번호 재입력, 취소, 다른 출처 인증 거부, HTTP 401/403 상태, 홈/피플카운팅 바로가기, 설정 파일 비밀번호 미저장을 검증합니다. 웹 검색·탭 추가/선택/삭제·모든 웹 창 닫기와 재추가·좌우/상하 비율·작은 창 배치·실제 창 녹화 MP4 저장과 Chromium 영상 재생도 검증합니다. 화면 색을 바꾸며 녹화하고, 완성된 MP4의 유한한 길이·앞뒤 시간 탐색 후 양쪽 화면 픽셀을 확인합니다. 실제 로컬 모의 PLC에 연결해 자동 녹화 기준값 무시·입장/퇴장 증감 감지·종료 연장·이전/이후 장면 보관·OFF 후 임시 버퍼 정리와 수동 녹화 복귀도 검증합니다. 외부 HTTPS 페이지는 모의 응답을 사용합니다. 자체 창 캡처를 지원하는 Windows 데스크톱이 필요하며 외부 네트워크 요청은 보내지 않습니다. Windows 배포 workflow는 이 테스트와 배포본 내장 FFmpeg 변환 검증이 통과해야 EXE를 게시합니다. 선택형 PC 소리는 실제 오디오 장치에서 별도로 확인해야 합니다.

내장 영상 변환기의 저작권·라이선스와 소스 위치는 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)를 참고하세요.

실제 Windows GUI, 카메라 영상·로그인, YouTube 영상 재생, 실제 PLC 값의 일치는 현장 PC에서 확인해야 합니다. 카메라와 PLC 사설 IP에 클라우드에서 연결을 시도하지 않습니다.

- [people-count-monitor](https://github.com/seoljaegeun3-svg/people-count-monitor): 카메라·YouTube·PLC 통합 모니터. 이전 GitHub 이름은 `1`입니다.
- [people-counter-native](https://github.com/seoljaegeun3-svg/people-counter-native): Go 기반 Windows 네이티브 PeopleCounter와 LS XGT 통신. 이전 GitHub 이름은 `insurance-ai-marketing`입니다.

두 원격 저장소의 이름 변경을 완료했습니다. 클라우드 체크아웃 경로는 `/workspace/1`이며, Git origin은 새 `people-count-monitor` 주소를 사용합니다.

클라우드의 GitHub 인증 전달 경로 때문에 관리 토큰이 적용되지 않는 경우 **Settings → Secrets and variables → Actions → New repository secret**에 `REPO_ADMIN_TOKEN`으로 기존 관리 토큰을 등록하고 **Actions → Rename project repositories → Run workflow**를 실행합니다. workflow는 등록한 GitHub Secret을 사용해 GitHub runner에서 위 두 저장소를 변경합니다. 누락된 Secret·접근 실패·이름 충돌은 변경 전에 중단하고, 완료된 이름 변경은 다시 실행해도 건너뜁니다. 토큰 값을 채팅이나 workflow 입력값에 넣지 마세요.
